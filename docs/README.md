# LocalHarnessMaker 작업 문서

작성 기준: 2026-10-14, Asia/Seoul. 현재 단계는 실행 전 준비입니다. 교사 생성 입력, 기능 평가기·제출 서비스 격리·익명 패키징을 구현하고 참조 앱으로 검증했습니다. 개발 성능 개선을 입증한 결과는 아직 없습니다.

## 프로젝트 목적

사용자가 평소처럼 개발 요청을 입력하면, 로컬 LLM이 프로젝트 맥락을 확인하고 필요한 질문과 요구사항 구체화, 기술 제안을 수행합니다. Codex가 처음부터 사용자 의도에 맞는 결과물을 만들도록 도와 **오해와 누락으로 인한 반복 수정**을 줄이는 것이 목적입니다.

학생 모델은 Gemma 4 12B, 교사 모델은 GPT 6.1 SOL로 지정합니다. 먼저 교사를 통해 여러 분야의 프로젝트와 최초 요청을 만들고, 구체화 수준과 기술 제안의 효과를 실제 개발 및 결과물 블라인드 평가로 검증합니다. 효과를 확인한 뒤 학생 모델 증류와 hook 통합을 진행합니다.

## 다음 작업

입력 자료는 [파일럿 자료](../experiments/pilot-v1/README.md), 생성·검토 이력은 [준비 보고서](experiments/pilot-v1-preparation.md)에 있습니다.

다양성 확대 자료로 [12개 프로젝트 풀](../experiments/project-pool-v1/README.md)과 [확대 준비 보고서](experiments/project-pool-v1-preparation.md)를 추가했습니다. 기존 두 파일럿을 먼저 실행할 순서는 유지합니다. 추가 원본 10개의 코드와 A~E 전체는 아직 준비하지 않았습니다.

평가기와 검증 기록은 [harness](../harness/README.md), [검증 보고서](experiments/harness-v1-validation.md)에 있습니다. 정상 시나리오 30개와 결함 16종으로 도구를 확인했습니다. 이는 교사 개발의 개선 효과 측정과 구분합니다.

1. 실제 Codex 개발 세션의 숨은 자료·다른 군·공개 원본 접근을 통제하고 공통 의존성 설치 방식을 정합니다.
2. 질문·답변·완료·수정 회차를 실제 교사 세션과 연결하고 첫·최종 제출과 사용량을 보존합니다.
3. 실제 평가자 계정의 접근 분리와 익명 패키지의 신원 누출 검수를 확인합니다.
4. 모델·추론 설정, 반복 수, 실행·사용량·비용 한도와 평가 담당자를 확정해 프로토콜을 고정합니다.
5. 작은 파일럿으로 실제 개발·평가 절차를 확인합니다.

세부 체크리스트는 [진행 순서](03-roadmap.md), 새 작업에서 이어받을 내용은 [컨텍스트와 인계](04-context-and-handoff.md)를 참조합니다.

## 문서의 상태 구분

- **확정 목표:** 사용자가 명시한 제품 목적과 실험 우선 방향입니다.
- **설계 제안:** A~E 비교군, 기록 형식, 파일럿 규모 등 실행 전에 확정할 초안입니다.
- **도구 검증:** 참조 앱의 30개 시나리오·결함 16종과 제출 서비스 격리·패키징 검사입니다. 제품 성능 개선 결과와 구분합니다.
- **개발 성능 결과:** 실제 교사 개발과 A~E 블라인드 비교에서 확인할 사실입니다. 현재는 없습니다.
- **준비 확인:** 교사 생성 호출과 브라우저 런타임, 입력 자료의 구조·체크섬 검증입니다. 개발 성능 검증과 구분합니다.
- **미확정:** 실행 예산, 모델의 정확한 버전, 품질 기준 수치 등 아직 결정하지 않은 항목입니다.

루트 [README](../README.md)는 초기의 저가 모델용 하네스·오케스트레이션 설계도 보존합니다. 현재 제품 범위는 이 문서 모음의 확정 목표를 따르며, 실험 프로토콜의 제안을 이미 입증된 효과로 해석하지 않습니다.

## 기록 유지

- 목표가 바뀌면 [제품 방향](01-product-direction.md)과 [컨텍스트와 인계](04-context-and-handoff.md)를 함께 갱신합니다.
- 실험 조건은 실행 전에 버전을 고정합니다. 조건을 바꾸면 새 버전과 변경 이유를 남깁니다.
- 단계가 끝나면 [진행 순서](03-roadmap.md)의 상태 및 인계 문서의 결과 경로·다음 작업을 갱신합니다.
- 실험 보고서는 `docs/experiments/` 아래에 추가합니다. 원시 실행 기록과 결과물은 크기 및 데이터 성격에 맞는 저장소에 보관하고, 보고서에 버전·해시·접근 경로를 적습니다.
- 블라인드 ID와 실험군의 대응표는 평가자에게 노출되는 보고서나 결과물에 포함하지 않습니다. 평가가 끝나기 전 공개 GitHub 경로에 올리지 않습니다.
