# 04. 컨텍스트와 인계

작성 기준: 2026-10-14, Asia/Seoul. 새 대화나 다음 작업에서 목적과 진행 순서를 이어받기 위한 문서입니다.

## 1. 현재 목표

사용자가 Codex를 통해 개발할 때, Gemma 4 12B 기반 로컬 LLM을 hook에 연결해 필요한 질문, 요구사항 구체화와 기술 제안을 수행합니다. 사용자가 의도와 다른 결과물을 받고 반복 수정하는 일을 줄이며 첫 결과물의 품질을 높이는 것이 목적입니다.

질문과 추천은 실제 개발 실험에서 효과를 확인한 근거에 기반해야 합니다. GPT 6.1 SOL이 여러 분야의 프로젝트와 자연스러운 최초 요청을 생성하고, 구체화 정도가 다른 요청으로 끝까지 개발합니다. 첫 제출과 최종 결과물을 블라인드 평가해 효과를 확인한 뒤 증류로 이어갑니다.

## 4. 현재 저장소 상태

- 문서 모음과 루트 README의 최신 방향 안내를 작성했습니다.
- 기존 README의 초기 하네스 설계는 보존했습니다.
- `gpt-6.1-sol`을 명시한 실제 CLI 호출로 식재료 소비 일정판과 장비 예약 API의 원본 및 A~E 요청을 생성했습니다.
- 필수 요구사항은 14개, 브라우저·HTTP 판정 시나리오는 30개입니다. 모의 사용자 답변과 수정 피드백도 준비했습니다.
- 생성 원본의 빈 `then` 필드 30개와 종료 시각 표현 1개를 기록하며 보정했습니다. 원본과 변경 내역을 보존했습니다.
- ChatGPT 기기 로그인 복구 후 생성 호출 2회가 성공했고 Chromium 실행을 확인했습니다. 인증 정보와 원시 로그는 Git에 넣지 않았습니다.
- 입력의 구조·참조·E의 정확한 접합과 SHA-256 목록을 검증하는 스크립트를 추가했습니다.
- 실제 개발 코드와 구체화·질문·추천의 성능을 입증한 결과는 아직 없습니다.
- 기능 평가기, 실험 실행기, 학습 데이터셋·학생 어댑터와 운영 hook 구현은 아직 없습니다.
- `experiments/project-pool-v1/`에는 기존 두 원본을 참조하는 12개 목록, 신규 원본 10개, 전체 24개 명확성 프로필 연결이 있습니다. 전체 요구사항 74개와 판정 시나리오 127개를 다룹니다.
- 기술 후보·기존 기술 유지·추천 보류는 각 4개의 설계 조건입니다. 명확성·질문 필요성·기술 정책 라벨은 실증적 학습 정답이 아닙니다.
- 확대 원본의 계약·표현 8개 보정은 원본과 변경 이력으로 기록했습니다. 기존 변경 과제 8개의 시작 코드는 아직 materialize하지 않았습니다.
- 교사 생성은 기존 파일럿 2회와 확대 4회가 성공했습니다. 확대 자료 검증은 `scripts/validate_project_pool.py`로 수행합니다.

입력 자료는 [experiments/pilot-v1/README.md](../experiments/pilot-v1/README.md), 상세 이력은 [준비 보고서](experiments/pilot-v1-preparation.md)에서 확인합니다. 교사 원본 생성·검토를 다시 처음부터 반복하지 않습니다.

확대 자료는 [project-pool-v1/README.md](../experiments/project-pool-v1/README.md), [확대 준비 보고서](experiments/project-pool-v1-preparation.md)에 있습니다. 기존 파일럿 A~E는 변경하지 않았으며, 추가 10개의 A~E는 아직 없습니다. 120회는 향후 규모 계산입니다.

원격 반영 커밋은 Git 이력에서 확인합니다. 이후 실행한 산출물과 결과 경로는 이 절과 진행 순서 문서에 갱신합니다.

## 5. 검증해야 할 전제

- 구체화가 기본 Codex보다 첫 결과물과 수정 부담을 개선하는가?
- 질문으로 얻는 정보가 사용자 답변 부담보다 큰 이익을 주는가?
- 상세화가 필요한 수준은 작업 유형과 기존 환경에 따라 어떻게 달라지는가?
- 기술 추천의 효과가 특정 프로젝트·조건 밖에서도 유지되는가?
- 교사에서 확인한 효과를 학생 모델이 유지할 수 있는가?
- 대상 Codex 환경에서 질문 표시·보류·답변 재개를 hook으로 연결할 수 있는가?

기존에 확인한 `UserPromptSubmit`은 추가 맥락과 진행 차단을 지원하지만 원문 교체 필드는 확인되지 않았습니다. hook 통합 시 적용 버전에서 다시 확인합니다. 질문 UI와 상태 관리는 구현할 부분입니다.

## 6. 다음 작업과 아직 하지 않을 작업

다음 작업은 [진행 순서](03-roadmap.md)의 단계 0 남은 항목입니다. 이미 만든 원본·A~E 요청·평가 기준을 사용해 격리된 시작 작업 공간, 기능 평가기와 질문·수정 실행 경로를 준비합니다.

파일럿 규모·시간·질문·수정 한도는 초안이고 총사용량·비용 한도와 평가 담당자 등은 미확정입니다. 준비 자료의 체크섬을 프로토콜 동결이나 개발 성능 검증으로 표현하지 않습니다. 기기 인증은 성공했지만 다음 환경에서도 실제 호출이 가능한지 확인합니다.

효과 검증 전에 학생 증류·자동 재학습·여러 실행 모델의 배치를 먼저 구현하지 않습니다. 작은 기술 확인은 가능하지만 품질 개선을 입증한 결과와 구분합니다.

## 7. 재개용 프롬프트

다음 작업에서 아래 내용을 사용할 수 있습니다.

> LocalHarnessMaker의 `docs/README.md`, 01~04와 두 준비 보고서를 읽고 이어서 작업하라. 학생은 Gemma 4 12B, 교사는 GPT 6.1 SOL이다. 목적은 질문·구체화·기술 제안으로 Codex의 첫 결과물 품질을 높이고 사용자 수정 부담을 줄이는 것이다. 기존 두 원본과 A~E는 `experiments/pilot-v1/`, 그 두 개를 포함한 12개 원본 풀은 `experiments/project-pool-v1/`에 있다. 두 validate 스크립트의 `--check-hashes`로 확인하고 원본을 다시 생성하지 마라. 실제 개발·블라인드 평가·증류는 미실행이다. 먼저 기존 두 파일럿의 격리·30개 기능 판정·질문 및 수정 연결·익명 평가 패키지를 준비하고 실행 조건을 고정하라. 확대 원본 10개의 시작 코드와 A~E는 아직 없으며 기존 과제 8개는 블루프린트다. 명확성·기술 정책은 가설로 다루고 코드에서 알 수 있는 내용을 사용자에게 다시 묻지 마라. 작업 후 진행·인계 기록을 갱신하라.
