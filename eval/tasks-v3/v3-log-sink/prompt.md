Separate record formatting from batched delivery in logsink.py. Keep Sink(send, capacity=3), emit(level, message), flush(), and expose the pure format_record(level, message) -> bytes function. send accepts a tuple of bytes and returns normally on success or raises on failure; it does not reenter this Sink.
LS1. format_record returns UTF-8 bytes for level.upper() + ': ' + escaped_message + one actual LF. Escape each backslash as two backslashes, CR as literal backslash-r, and LF as literal backslash-n, in that order; leave all other characters unchanged, including tabs and Unicode. Formatting does no I/O. Each accepted emit calls the current module format_record exactly once; flush never formats again.
LS2. Buffer records in emission order. Reaching capacity automatically flushes the whole pending batch. flush on empty does nothing. send receives an immutable tuple and a successful send retires exactly that batch. emit and flush return None. A partial final batch stays buffered until explicit flush. Separate sinks share no pending state. capacity must have type int (not bool) and be >0, else raise ValueError('capacity') before any send.
LS3. If send raises, propagate the same exception and retain the entire failed batch, without automatic retry. Explicit flush retries identical bytes. When an earlier failed batch already fills capacity, the next emit must flush it before formatting or accepting the new record. If that preflush fails, do not format/enqueue the new record; if it succeeds, accept the new record normally. A formatter exception never enqueues its record. Ownership changes only after successful send.
LS4. Preserve public signatures and bytes, and keep formatting independently replaceable without changing transport buffering. Add regression tests for backpressure, failure ownership and formatter call counts.

Use Python 3.11+ and the standard library. Add regression tests as needed.
