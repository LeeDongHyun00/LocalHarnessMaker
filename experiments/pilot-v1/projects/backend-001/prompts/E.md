공유 작업실 운영자와 내부 프로그램이 장비 예약을 기록하고 중복 예약을 방지할 수 있는 API를 만들어 주세요.
- 장비 조회는 200과 배열을 반환하며 초기 목록은 비어 있습니다. 장비 등록은 201과 객체를 반환하고 이름 앞뒤 공백을 제거합니다. 같은 이름도 별도로 등록할 수 있으며 각 등록의 id는 고유합니다.
- 존재하는 장비에 대여자와 시작·종료 시각으로 예약을 생성합니다. 대여자 앞뒤 공백을 제거하고, 성공 시 201과 고유 id 및 status가 active인 예약 객체를 반환합니다.
- 같은 장비의 active 예약끼리만 충돌을 검사합니다. 시간 구간은 시작 포함·종료 제외이며, 겹치면 409와 conflict를 반환하고 추가하지 않습니다. 앞 예약의 종료 시각에 다음 예약을 시작할 수 있고 서로 다른 장비는 같은 시간에 예약할 수 있습니다.
- 취소는 200과 status가 cancelled인 예약 객체를 반환합니다. 취소 기록은 남기되 충돌에서 제외하고, 반복 취소도 같은 id의 cancelled 객체와 200을 반환합니다.
- 예약 조회는 200과 배열을 반환합니다. equipment_id와 status 필터를 각각 또는 함께 적용하며 함께 쓰면 두 조건을 모두 적용합니다. status는 active와 cancelled만 허용합니다. 시작 시각 오름차순으로 정렬하고 같은 시각은 생성 순서를 유지합니다. 존재하지 않는 장비 id로 조회하면 200과 빈 배열을 반환합니다.
- 필수 필드 누락, 잘못된 필드 타입, 공백뿐인 name·borrower, 유효하지 않은 UTC 날짜나 지정된 시간 형식 위반, 종료 시각이 시작 이하인 경우, 잘못된 JSON, 허용되지 않은 status 필터는 400과 invalid_input을 반환합니다. 나머지 형식이 유효한 예약 요청에서 없는 장비를 참조하거나 없는 예약을 취소하면 404와 not_found를 반환합니다. 오류에는 비어 있지 않은 설명을 제공하고 기록을 변경하지 않습니다.
- 같은 저장 위치로 서버를 정상 종료하고 재시작해도 장비, 예약, 취소 상태의 기존 id와 정보를 유지합니다. 저장 위치 설정 방법은 실행 안내에 설명합니다.
- 인증과 사용자 권한, 장비 수정·삭제, 예약 시간 변경, 반복 예약, 알림 발송은 범위에서 제외합니다. 순차 요청과 정상 재시작을 대상으로 하며 동시 요청의 경쟁 상황, 부하, 비정상 종료 복구는 범위에서 제외합니다.

기술 제안은 검증 전 가설입니다. 제공된 Python 3.12의 표준 라이브러리인 http.server, sqlite3, json, datetime, uuid를 활용하는 구성을 후보로 제안합니다. SQLite로 장비와 예약 상태를 저장하고, 시간 문자열의 형식과 실제 UTC 날짜를 확인한 뒤 비교하며, 충돌 조건을 기존 시작 < 새 종료 및 새 시작 < 기존 종료로 표현하면 요구된 동작을 구현하는 데 도움이 될 것으로 예상합니다.
