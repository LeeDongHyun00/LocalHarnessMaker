# 가정 식재료 소비 일정판 평가 체크리스트

상태: 실행 전 초안. 교사 생성 요구사항에 작업 에이전트의 형식·일관성 검토를 반영했습니다. 기능 평가는 아직 하지 않았습니다.

아래 모든 acceptance를 통과해야 해당 요구사항은 pass입니다. 필수 기능의 실제 동작을 평가하며 내부 기술을 정답으로 강제하지 않습니다.

## F1 — 핵심

이름, 양의 정수 수량, 유효한 소비기한을 입력해 식재료를 등록하고 목록에서 세 값을 확인할 수 있어야 한다. 처음에는 목록이 비어 있어야 한다.

판정 방법: browser

- [ ] 시나리오 1: 이 앱의 저장 기록이 없는 브라우저에서 앱을 연 상태다. → 목록을 확인하면 → 등록된 재료가 없다는 안내가 보인다.
- [ ] 시나리오 2: 식재료 목록이 비어 있다. → 이름 우유, 수량 2, 소비기한 2026-10-15를 입력하고 등록하면 → 목록에 우유, 2, 2026-10-15가 표시된다.

미충족 시 피드백: 재료를 등록하면 이름, 수량, 소비기한이 목록에 모두 보이게 해 주세요.

## F2 — 핵심

각 식재료를 한 개씩 소비 처리할 수 있어야 한다. 수량이 0이 되면 해당 재료를 목록에서 제거한다.

판정 방법: browser

- [ ] 시나리오 1: 우유 수량이 2개다. → 우유의 한 개 소비 기능을 실행하면 → 우유 수량이 1개로 표시된다.
- [ ] 시나리오 2: 우유 수량이 1개다. → 우유의 한 개 소비 기능을 실행하면 → 우유가 목록에서 사라진다.

미충족 시 피드백: 한 개 소비할 때 수량을 줄이고 마지막 한 개를 소비하면 목록에서 지워 주세요.

## F3 — 핵심

사용자가 기준일을 변경할 수 있어야 한다. 전체, 기한 지남, 임박 필터를 제공한다. 기한 지남은 소비기한이 기준일보다 앞선 재료이며, 임박은 기준일부터 2일 뒤까지 양 끝 날짜를 포함한 재료다. 초기 기준일은 실행 환경의 오늘 날짜다.

판정 방법: browser

- [ ] 시나리오 1: 기준일이 2026-10-14이고 요구르트는 2026-10-13, 두부는 2026-10-14, 우유는 2026-10-15, 치즈는 2026-10-16, 달걀은 2026-10-20이 소비기한이다. → 임박 필터를 선택하면 → 두부, 우유, 치즈만 표시된다.
- [ ] 시나리오 2: 앞의 다섯 재료가 등록되어 있고 기준일은 2026-10-14다. → 기한 지남 필터를 선택하면 → 요구르트만 표시된다.
- [ ] 시나리오 3: 같은 재료가 등록되어 있고 임박 필터가 선택되어 있다. → 기준일을 2026-10-15로 바꾸면 → 우유와 치즈만 표시된다.

미충족 시 피드백: 기준일을 바꿀 수 있게 하고 임박 범위를 기준일부터 이틀 뒤까지로 맞춰 주세요.

## F4

이름 부분 문자열 검색을 제공하고 검색어 앞뒤 공백을 무시한다. 검색과 기한 필터는 동시에 적용한다. 결과는 소비기한 오름차순으로 표시하며 같은 소비기한에서는 등록 순서를 유지한다.

판정 방법: browser

- [ ] 시나리오 1: 기준일은 2026-10-14이며 우유는 2026-10-15, 저지방 우유는 2026-10-20, 두부는 2026-10-14다. → 임박 필터에서 검색어 ' 우유 '를 입력하면 → 우유만 표시된다.
- [ ] 시나리오 2: 우유 2026-10-15, 두부 2026-10-14, 치즈 2026-10-15 순으로 등록되어 있다. → 전체 필터를 선택하고 검색어를 비우면 → 두부, 우유, 치즈 순으로 표시된다.

미충족 시 피드백: 이름 검색과 기한 필터를 함께 적용하고 소비기한 순으로 정렬해 주세요.

## F5

등록된 식재료와 소비 처리 결과는 같은 브라우저에서 새로고침하거나 앱을 다시 열어도 유지되어야 한다.

판정 방법: browser

- [ ] 시나리오 1: 우유 2개를 등록하고 한 개를 소비해 수량이 1개다. → 페이지를 새로고침하면 → 우유의 수량 1과 기존 소비기한이 유지된다.
- [ ] 시나리오 2: 수량 1인 우유를 마지막으로 소비 처리했다. → 같은 브라우저에서 앱을 다시 열면 → 우유가 다시 나타나지 않는다.

미충족 시 피드백: 새로고침해도 등록 내용과 소비 처리 결과가 유지되게 해 주세요.

## F6

공백뿐인 이름, 양의 정수가 아닌 수량, 존재하지 않는 날짜로는 등록할 수 없어야 한다. 문제 있는 입력을 알리는 안내를 제공하고 기존 재료를 유지한다.

판정 방법: browser

- [ ] 시나리오 1: 우유 2개가 등록되어 있다. → 이름을 공백만 입력하거나 수량을 0으로 입력해 등록을 시도하면 → 문제 있는 입력에 대한 안내가 보이고 목록에는 기존 우유만 남는다.
- [ ] 시나리오 2: 기존 재료가 등록되어 있다. → 수량 1.5 또는 소비기한 2026-02-30으로 등록을 시도하면 → 등록이 차단되고 입력 오류 안내가 제공되며 기존 재료는 유지된다.

미충족 시 피드백: 잘못된 수량이나 날짜가 저장되지 않게 하고 고칠 입력을 알려 주세요.

## F7

검색 또는 필터 결과가 없으면 결과가 없다는 안내를 표시한다. 등록, 검색, 필터 변경, 소비 처리를 키보드로 수행할 수 있고 입력과 버튼의 목적을 알아볼 수 있어야 한다.

판정 방법: browser

- [ ] 시나리오 1: 우유만 등록되어 있다. → 검색어 사과를 입력하면 → 검색 결과가 없다는 안내가 표시된다.
- [ ] 시나리오 2: 앱을 열고 포인팅 장치를 사용하지 않는다. → 키보드로 이름과 수량과 날짜를 입력해 등록하고 검색과 필터 변경과 소비 처리를 수행하면 → 각 동작이 가능하며 현재 조작 중인 요소와 그 목적을 확인할 수 있다.

미충족 시 피드백: 결과가 없는 이유를 안내하고 주요 조작을 키보드로도 할 수 있게 해 주세요.

## 결과 기록

각 요구사항은 pass / fail / not_evaluated로 기록합니다. 첫 제출과 최종 제출을 따로 기록하고 증거 경로·실행 환경·오류 원인을 연결합니다. 측정 오류를 기능 실패나 성공으로 바꾸지 않습니다.
