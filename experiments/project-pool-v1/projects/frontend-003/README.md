# 폼 상태와 키보드 조작 오류 수정

상태: 교사 생성 후 설계 검토. 구현·기능 평가·블라인드 평가는 미실행입니다.

- 분야: frontend
- 작업: bug_fix
- 시작 상태: baseline_not_materialized
- 기술 제안 조건: withhold — 실험 설계 가설

로컬 문의 폼에서 입력 손실, 중복 제출과 키보드 조작 결함을 수정한다.

## 요구사항

| ID | 범위 | 핵심 | 내용 |
| --- | --- | --- | --- |
| R1 | change | 예 | 유효성 오류가 발생해도 모든 입력을 보존한다. 이름과 메시지는 공백만 있으면 오류이며 이메일은 공백 없는 로컬 부분, @, 점을 포함한 도메인 구조를 요구한다. 오류는 해당 필드와 연결하여 표시하고 첫 오류 필드로 포커스를 이동한다. |
| R2 | change | 예 | 확인 대화상자는 열릴 때 취소 버튼에 포커스를 두고 Tab 및 Shift+Tab 이동을 내부 버튼에 한정한다. Escape와 취소 버튼은 전송 없이 대화상자를 닫고 검토 버튼으로 포커스를 돌리며 입력을 보존한다. |
| R3 | change | 아니오 | 메시지 입력의 Enter는 줄바꿈을 삽입하며 검토나 전송을 실행하지 않는다. 검토 버튼과 대화상자 버튼은 Enter 및 Space로 실행할 수 있다. |
| R4 | change | 예 | 전송 중 반복 클릭이나 키보드 실행은 추가 요청을 만들지 않는다. 전송 중 취소와 전송 버튼은 비활성화되고 Escape로 닫히지 않는다. 성공하면 대화상자를 닫고 입력을 비우며 접수 번호를 표시한다. |
| R5 | change | 아니오 | 서버 실패 시 대화상자와 입력을 유지하고 '전송하지 못했습니다. 다시 시도해 주세요'를 표시한다. 버튼을 다시 활성화하여 동일 내용으로 재시도할 수 있게 한다. |
| R6 | preserve | 아니오 | 기존 필드 이름과 보이는 레이블, 유효한 입력의 확인 요약 및 POST 계약을 보존한다. 확인 요약과 전송 본문은 입력 문자열을 그대로 사용하며 검토만으로는 요청을 보내지 않는다. |

## 실행 전 주의

기존 과제의 시작 상태는 아직 준비하지 않은 블루프린트입니다. 실제 저장소·커밋·비회귀 결과를 확보한 뒤 실행합니다. 생략된 결정은 요청 본문에서 빠졌다는 뜻이며, 코드나 공통 맥락에서 확인할 수 있으면 사용자에게 다시 묻지 않습니다. 명확성·기술 정책 라벨은 실증적 학습 정답이 아닙니다.

CLI 시나리오의 `\n`, `\r`, `\t` 표기는 해당 실제 제어 문자로 fixture를 구성합니다. 합격 판정은 해당 원본의 모든 acceptance를 기준으로 하며 측정 오류는 not_evaluated로 구분합니다.
