# 인코딩·부분 실패 처리 수정

상태: 교사 생성 후 설계 검토. 구현·기능 평가·블라인드 평가는 미실행입니다.

- 분야: cli_data
- 작업: bug_fix
- 시작 상태: baseline_not_materialized
- 기술 제안 조건: withhold — 실험 설계 가설

여러 텍스트 파일의 줄 수를 집계하는 CLI에서 인코딩 오판과 파일 단위 실패 전파를 수정한다.

## 요구사항

| ID | 범위 | 핵심 | 내용 |
| --- | --- | --- | --- |
| R1 | change | 예 | 파일마다 manifest에 명시된 utf-8 또는 cp949로 엄격하게 디코딩하고 인코딩을 추측하거나 대체 문자를 삽입하지 않는다. |
| R2 | change | 예 | 파일 없음과 디코딩 실패를 항목 오류로 기록하고 모든 나머지 항목의 처리를 계속한다. |
| R3 | change | 아니오 | 처리가 완료되면 일부 또는 모든 파일 실패에도 보고서를 저장한다. 항목 오류가 있으면 종료 코드 2, 없으면 0이며 summary 집계는 실제 항목 결과와 일치한다. |
| R4 | preserve | 아니오 | 기존 줄 수 계산을 보존한다. LF, CRLF와 단독 CR을 줄 구분자로 사용하고 마지막 구분자 뒤에 추가 빈 줄을 세지 않는다. 빈 파일은 0줄이다. |
| R5 | preserve | 아니오 | manifest 순서와 id, manifest 기준 상대 경로 해석을 보존하고 원본 텍스트 파일을 변경하지 않는다. |
| R6 | preserve | 예 | manifest 자체의 구문·구조 오류, 중복 id, 지원하지 않는 encoding은 기존처럼 전체 실행 실패로 처리한다. 파일 처리 전에 코드 1과 stderr 진단을 내고 기존 보고서를 보존한다. |

## 실행 전 주의

기존 과제의 시작 상태는 아직 준비하지 않은 블루프린트입니다. 실제 저장소·커밋·비회귀 결과를 확보한 뒤 실행합니다. 생략된 결정은 요청 본문에서 빠졌다는 뜻이며, 코드나 공통 맥락에서 확인할 수 있으면 사용자에게 다시 묻지 않습니다. 명확성·기술 정책 라벨은 실증적 학습 정답이 아닙니다.

CLI 시나리오의 `\n`, `\r`, `\t` 표기는 해당 실제 제어 문자로 fixture를 구성합니다. 합격 판정은 해당 원본의 모든 acceptance를 기준으로 하며 측정 오류는 not_evaluated로 구분합니다.
