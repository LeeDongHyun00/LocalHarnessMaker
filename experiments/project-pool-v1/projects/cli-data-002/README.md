# 기존 변환기의 새 형식 지원

상태: 교사 생성 후 설계 검토. 구현·기능 평가·블라인드 평가는 미실행입니다.

- 분야: cli_data
- 작업: feature_extension
- 시작 상태: baseline_not_materialized
- 기술 제안 조건: maintain_existing — 실험 설계 가설

기존 JSON 배열 변환기에 스트리밍 생산자가 전달하는 NDJSON 입력 형식을 추가한다.

## 요구사항

| ID | 범위 | 핵심 | 내용 |
| --- | --- | --- | --- |
| R1 | change | 예 | --format ndjson을 추가해 한 줄당 객체 하나를 읽으며 확장자로 형식을 추론하지 않는다. |
| R2 | change | 아니오 | NDJSON의 빈 줄과 공백만 있는 줄을 건너뛰고 객체의 원래 순서를 유지한다. 전부 빈 줄이면 헤더만 출력한다. |
| R3 | change | 예 | NDJSON의 구문 오류, 객체가 아닌 값, 선택 필드의 배열·객체 값은 전체 실패로 처리한다. 첫 오류의 1부터 시작하는 물리적 줄 번호를 stderr에 표시하고 기존 출력을 보존한다. |
| R4 | change | 아니오 | NDJSON에서도 기존 필드 계약을 적용한다. --fields 순서를 헤더와 열 순서로 사용하고 누락 또는 null은 빈 문자열, 문자열은 원문, 불리언은 소문자, 숫자는 JSON 숫자 표현으로 출력한다. |
| R5 | preserve | 예 | 기존 JSON 배열 입력과 --format 생략 동작을 보존한다. JSON 배열의 행 순서와 필드 매핑, 빈 배열의 헤더 출력을 유지한다. |
| R6 | preserve | 아니오 | 기존 CSV 인용 및 JSON 입력 오류 보호를 보존한다. 쉼표·개행·큰따옴표 문자열은 CSV 재해석 시 동일하고 잘못된 JSON 입력은 코드 1로 기존 출력을 보존한다. |

## 실행 전 주의

기존 과제의 시작 상태는 아직 준비하지 않은 블루프린트입니다. 실제 저장소·커밋·비회귀 결과를 확보한 뒤 실행합니다. 생략된 결정은 요청 본문에서 빠졌다는 뜻이며, 코드나 공통 맥락에서 확인할 수 있으면 사용자에게 다시 묻지 않습니다. 명확성·기술 정책 라벨은 실증적 학습 정답이 아닙니다.

CLI 시나리오의 `\n`, `\r`, `\t` 표기는 해당 실제 제어 문자로 fixture를 구성합니다. 합격 판정은 해당 원본의 모든 acceptance를 기준으로 하며 측정 오류는 not_evaluated로 구분합니다.
