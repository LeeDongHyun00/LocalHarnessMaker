# 기존 문서 API의 권한 확장

상태: 교사 생성 후 설계 검토. 구현·기능 평가·블라인드 평가는 미실행입니다.

- 분야: backend
- 작업: feature_extension
- 시작 상태: baseline_not_materialized
- 기술 제안 조건: maintain_existing — 실험 설계 가설

기존 소유자 전용 문서 API에 문서별 읽기·편집 공유 권한을 추가하고 기존 문서 동작을 보존한다.

## 요구사항

| ID | 범위 | 핵심 | 내용 |
| --- | --- | --- | --- |
| R1 | change | 예 | 소유자는 문서별로 다른 로컬 사용자에게 viewer 또는 editor 권한을 부여하거나 교체할 수 있다. 성공은 204이며 권한 목록에는 사용자당 하나의 현재 권한만 나타난다. |
| R2 | change | 예 | viewer는 문서 조회만, editor는 조회와 title·body 수정을 할 수 있다. 공유 사용자의 문서 삭제와 권한 관리는 모두 403 forbidden으로 거절하고 상태를 변경하지 않는다. |
| R3 | change | 예 | 문서 목록에는 본인 소유 문서와 공유받은 문서만 중복 없이 포함한다. 존재하지 않는 문서와 접근 권한이 없는 문서의 단건 조회·수정·삭제·권한 관리 요청은 동일한 404 not_found로 응답한다. |
| R4 | change | 아니오 | 소유자의 공유 권한 회수는 204이며 없는 공유 항목을 다시 회수해도 204다. 회수 완료 후 다음 요청부터 해당 사용자의 접근과 목록 노출을 차단한다. |
| R5 | preserve | 아니오 | 기존 소유자 문서 생성·조회·부분 수정·삭제 계약을 보존한다. 생성은 201과 유일한 id의 문서, 조회·수정은 200과 문서, 삭제는 204다. 수정에서 생략한 필드와 ownerId는 유지한다. |
| R6 | change | 아니오 | 기존 테스트 사용자 검증을 보존한다. 누락되거나 알려지지 않은 X-Test-User는 401 unauthenticated다. 소유자가 요청한 잘못된 역할, 알 수 없는 공유 대상 또는 자기 자신 공유는 400 invalid_permission이며 기존 권한을 변경하지 않는다. |

## 실행 전 주의

기존 과제의 시작 상태는 아직 준비하지 않은 블루프린트입니다. 실제 저장소·커밋·비회귀 결과를 확보한 뒤 실행합니다. 생략된 결정은 요청 본문에서 빠졌다는 뜻이며, 코드나 공통 맥락에서 확인할 수 있으면 사용자에게 다시 묻지 않습니다. 명확성·기술 정책 라벨은 실증적 학습 정답이 아닙니다.

CLI 시나리오의 `\n`, `\r`, `\t` 표기는 해당 실제 제어 문자로 fixture를 구성합니다. 합격 판정은 해당 원본의 모든 acceptance를 기준으로 하며 측정 오류는 not_evaluated로 구분합니다.
