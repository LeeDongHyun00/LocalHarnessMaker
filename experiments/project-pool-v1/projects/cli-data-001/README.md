# CSV 정리 도구

상태: 교사 생성 후 설계 검토. 구현·기능 평가·블라인드 평가는 미실행입니다.

- 분야: cli_data
- 작업: new_build
- 시작 상태: new_workspace
- 기술 제안 조건: candidate — 실험 설계 가설

반복 수집한 CSV를 명시적인 정리 규칙에 따라 재현 가능한 파일로 만든다.

## 요구사항

| ID | 범위 | 핵심 | 내용 |
| --- | --- | --- | --- |
| R1 | deliver_new | 예 | CSV를 논리적 레코드로 읽고 헤더 순서와 인용 필드의 내용을 보존한다. |
| R2 | deliver_new | 아니오 | 모든 데이터 필드의 앞뒤 ASCII 공백과 탭을 제거하되 내부 공백과 헤더 이름은 변경하지 않는다. |
| R3 | deliver_new | 예 | 정리한 키 값으로 대소문자를 구분해 중복을 판단하고 첫 번째 유효 행을 남기며 입력 순서를 유지한다. |
| R4 | deliver_new | 예 | 열 수가 다르거나 정리 후 키가 빈 행은 거부하고 나머지 행을 처리한다. 일부 행 거부 시 종료 코드는 2다. |
| R5 | deliver_new | 아니오 | 보고서의 집계는 헤더를 제외하며 모든 입력 행을 출력·중복·거부 중 하나로 계산한다. 거부가 없으면 종료 코드는 0이다. |
| R6 | deliver_new | 아니오 | 입력 파일 없음, 존재하지 않는 키 열, 중복 헤더, 잘못된 UTF-8 또는 닫히지 않은 CSV 인용은 전체 실패로 처리한다. 종료 코드 1과 stderr 오류를 내고 기존 결과와 보고서를 변경하지 않는다. |

## 실행 전 주의

기존 과제의 시작 상태는 아직 준비하지 않은 블루프린트입니다. 실제 저장소·커밋·비회귀 결과를 확보한 뒤 실행합니다. 생략된 결정은 요청 본문에서 빠졌다는 뜻이며, 코드나 공통 맥락에서 확인할 수 있으면 사용자에게 다시 묻지 않습니다. 명확성·기술 정책 라벨은 실증적 학습 정답이 아닙니다.

CLI 시나리오의 `\n`, `\r`, `\t` 표기는 해당 실제 제어 문자로 fixture를 구성합니다. 합격 판정은 해당 원본의 모든 acceptance를 기준으로 하며 측정 오류는 not_evaluated로 구분합니다.
