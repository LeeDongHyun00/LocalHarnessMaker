## 요구사항

| ID | 범위 | 핵심 | 내용 |
| --- | --- | --- | --- |
| R1 | change | 예 | 예약 POST가 409 또는 500으로 실패하면 성공 표시와 임시 예약 상태를 제거하고 오류를 보여 준다. 이어서 현재 날짜를 재조회해 서버 좌석 상태를 표시한다. |
| R2 | change | 예 | 날짜별 조회 응답이 역순으로 도착해도 마지막으로 선택한 날짜와 그 날짜의 좌석만 표시한다. 이전 날짜 응답은 현재 날짜의 로딩·오류 상태도 바꾸지 않는다. |
| R3 | change | 예 | 같은 날짜·좌석의 예약 요청이 진행 중이면 해당 예약 버튼을 비활성화하여 중복 제출을 막는다. 예약 성공 후 현재 날짜를 재조회하며 새로고침 후에도 동일한 예약을 표시한다. |
| R4 | change | 아니오 | 현재 날짜 조회 실패는 빈 좌석 목록으로 표현하지 않는다. 해당 날짜의 조회 오류와 재시도 버튼을 표시하고 예약 조작을 막는다. 재시도 성공 시 오류를 지우고 조작을 복구한다. |
| R5 | preserve | 아니오 | 기존 서버의 날짜·좌석별 예약 유일성과 공개 응답 형식을 보존한다. 같은 날짜·좌석의 두 번째 예약은 409, SEAT_TAKEN이며 첫 예약은 유지된다. |
| R6 | preserve | 아니오 | 기존 날짜별 독립 조회와 예약의 영속성을 보존한다. 한 날짜의 예약은 다른 날짜의 같은 좌석에 영향을 주지 않으며 서버 재시작 후 유지된다. |

## 실행 전 주의

기존 과제의 시작 상태는 아직 준비하지 않은 블루프린트입니다. 실제 저장소·커밋·비회귀 결과를 확보한 뒤 실행합니다. 생략된 결정은 요청 본문에서 빠졌다는 뜻이며, 코드나 공통 맥락에서 확인할 수 있으면 사용자에게 다시 묻지 않습니다. 명확성·기술 정책 라벨은 실증적 학습 정답이 아닙니다.

CLI 시나리오의 `\n`, `\r`, `\t` 표기는 해당 실제 제어 문자로 fixture를 구성합니다. 합격 판정은 해당 원본의 모든 acceptance를 기준으로 하며 측정 오류는 not_evaluated로 구분합니다.
