# 기존 상품 목록의 검색·필터 확장

상태: 교사 생성 후 설계 검토. 구현·기능 평가·블라인드 평가는 미실행입니다.

- 분야: frontend
- 작업: feature_extension
- 시작 상태: baseline_not_materialized
- 기술 제안 조건: maintain_existing — 실험 설계 가설

기존 상품 목록에 검색과 조건 필터를 추가하여 원하는 상품을 빠르게 찾도록 한다.

## 요구사항

| ID | 범위 | 핵심 | 내용 |
| --- | --- | --- | --- |
| R1 | change | 예 | 상품명 검색은 입력 즉시 적용하며 앞뒤 공백을 제거한 부분 문자열로 비교한다. 빈 검색어는 모든 상품을 대상으로 한다. |
| R2 | change | 예 | 카테고리는 전체 또는 한 카테고리를 선택하며, 재고 있음 조건은 별도 체크박스로 제공한다. 검색·카테고리·재고 조건은 AND로 결합한다. |
| R3 | change | 아니오 | 현재 결과 수를 표시하고 결과가 없으면 '조건에 맞는 상품이 없습니다'를 표시한다. 전체 초기화 버튼은 검색어, 카테고리, 재고 조건을 기본값으로 돌린다. |
| R4 | change | 아니오 | 검색과 필터 상태는 현재 페이지 메모리에서만 유지한다. 상세 대화상자를 열고 닫을 때는 유지하며 페이지를 새로고침하면 기본값으로 돌아간다. |
| R5 | preserve | 예 | 기존 상품 카드의 상품명, 원화 가격, 카테고리, 재고 표시와 fixture 순서를 보존한다. 상세 버튼은 선택 상품의 이름과 설명을 대화상자에 표시하고 닫기 버튼으로 닫힌다. |
| R6 | change | 아니오 | 검색 입력, 카테고리 선택, 재고 체크박스와 초기화 버튼은 보이는 이름 및 접근 가능한 이름을 갖고 키보드로 조작할 수 있다. 기존 360px 화면에서의 카드 정보와 상세 버튼 접근성을 보존한다. |

## 실행 전 주의

기존 과제의 시작 상태는 아직 준비하지 않은 블루프린트입니다. 실제 저장소·커밋·비회귀 결과를 확보한 뒤 실행합니다. 생략된 결정은 요청 본문에서 빠졌다는 뜻이며, 코드나 공통 맥락에서 확인할 수 있으면 사용자에게 다시 묻지 않습니다. 명확성·기술 정책 라벨은 실증적 학습 정답이 아닙니다.

CLI 시나리오의 `\n`, `\r`, `\t` 표기는 해당 실제 제어 문자로 fixture를 구성합니다. 합격 판정은 해당 원본의 모든 acceptance를 기준으로 하며 측정 오류는 not_evaluated로 구분합니다.
