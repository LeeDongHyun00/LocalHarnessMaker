# 고객 요청 관리 서비스

상태: 교사 생성 후 설계 검토. 구현·기능 평가·블라인드 평가는 미실행입니다.

- 분야: fullstack
- 작업: new_build
- 시작 상태: new_workspace
- 기술 제안 조건: candidate — 실험 설계 가설

## 요구사항

| ID | 범위 | 핵심 | 내용 |
| --- | --- | --- | --- |
| R1 | deliver_new | 예 | 제목·내용·이메일을 검증하여 접수하고, 고유 접수 번호와 고객 조회 토큰을 반환한다. 제목과 내용은 공백 제거 후 비어 있으면 안 되며 이메일은 로컬 부분과 도메인을 포함해야 한다. 성공은 HTTP 201과 status new이며 잘못된 입력은 HTTP 400과 error.code VALIDATION_ERROR다. |
| R2 | deliver_new | 아니오 | 담당자는 상태별 목록을 조회한다. 필터를 생략하면 전체를 보여 주며 생성 시각 내림차순, 같은 시각이면 id 오름차순으로 정렬한다. |
| R3 | deliver_new | 예 | 상태는 new→in_progress→resolved 순서로만 전환한다. 역방향 전환과 단계 건너뛰기는 HTTP 409로 거절하고 상태를 유지한다. 해당 오류의 error.code는 INVALID_TRANSITION이다. |
| R4 | deliver_new | 예 | 공개 답변과 내부 메모를 저장한다. 고객 조회에는 공개 답변만 포함하며, 담당자 조회에는 두 종류 모두 포함한다. 잘못된 고객 토큰은 HTTP 403으로 거절한다. 잘못된 토큰의 error.code는 FORBIDDEN이다. |
| R5 | deliver_new | 아니오 | 브라우저에서 접수, 고객 조회, 담당자 목록·상태 변경·메시지 작성을 수행할 수 있다. 성공 결과는 화면에 반영하며 실패하면 입력을 유지하고 오류를 표시한다. |
| R6 | deliver_new | 아니오 | 접수, 상태, 메시지와 고객 토큰은 같은 데이터 디렉터리로 서버를 재시작해도 유지된다. |

## 실행 전 주의

기존 과제의 시작 상태는 아직 준비하지 않은 블루프린트입니다. 실제 저장소·커밋·비회귀 결과를 확보한 뒤 실행합니다. 생략된 결정은 요청 본문에서 빠졌다는 뜻이며, 코드나 공통 맥락에서 확인할 수 있으면 사용자에게 다시 묻지 않습니다. 명확성·기술 정책 라벨은 실증적 학습 정답이 아닙니다.

CLI 시나리오의 `\n`, `\r`, `\t` 표기는 해당 실제 제어 문자로 fixture를 구성합니다. 합격 판정은 해당 원본의 모든 acceptance를 기준으로 하며 측정 오류는 not_evaluated로 구분합니다.
