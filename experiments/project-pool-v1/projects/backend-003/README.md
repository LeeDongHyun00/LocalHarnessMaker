## 요구사항

| ID | 범위 | 핵심 | 내용 |
| --- | --- | --- | --- |
| R1 | change | 예 | 유효한 신규 이벤트는 이벤트 기록과 잔액에 한 번 반영하고 201과 {eventId,status:"applied"}를 반환한다. 동일 eventId·accountId·delta 재전송은 200과 {eventId,status:"duplicate"}이며 잔액을 다시 바꾸지 않는다. |
| R2 | change | 아니오 | 동일 eventId를 다른 accountId 또는 delta로 재사용하면 409 event_conflict로 거절하고 최초 이벤트와 모든 계정 잔액을 보존한다. eventId의 유일성 범위는 전체 API다. |
| R3 | change | 예 | 예약 후 실패한 이벤트는 적용된 것으로 남지 않아야 한다. 실패 직후 이벤트 조회는 404 not_found이고 잔액은 유지된다. 동일 이벤트 재시도는 신규 적용에 성공해야 한다. |
| R4 | change | 예 | 같은 내용의 동일 이벤트를 동시에 두 번 전송해도 정확히 한 요청만 신규 적용하고 다른 요청은 중복으로 응답한다. 서로 다른 이벤트가 같은 계정에 동시에 도착하면 두 delta를 모두 반영한다. |
| R5 | preserve | 아니오 | 기존 정상 단건 처리와 조회 계약을 보존한다. 서로 다른 이벤트는 각각 적용하며 음수와 0 delta도 허용하고 잔액 하한을 추가하지 않는다. 없는 계정·이벤트 조회는 404 not_found다. |
| R6 | preserve | 아니오 | 기존 입력 검증을 보존한다. eventId는 공백만으로 구성되지 않은 문자열이고 delta는 -1000000부터 1000000까지의 정수여야 한다. 필수 값 누락·잘못된 타입·범위 위반은 400 invalid_event, 미등록 accountId는 404 account_not_found다. 거절한 요청은 ID를 소비하지 않으며 상태를 바꾸지 않는다. |

## 실행 전 주의

기존 과제의 시작 상태는 아직 준비하지 않은 블루프린트입니다. 실제 저장소·커밋·비회귀 결과를 확보한 뒤 실행합니다. 생략된 결정은 요청 본문에서 빠졌다는 뜻이며, 코드나 공통 맥락에서 확인할 수 있으면 사용자에게 다시 묻지 않습니다. 명확성·기술 정책 라벨은 실증적 학습 정답이 아닙니다.

CLI 시나리오의 `\n`, `\r`, `\t` 표기는 해당 실제 제어 문자로 fixture를 구성합니다. 합격 판정은 해당 원본의 모든 acceptance를 기준으로 하며 측정 오류는 not_evaluated로 구분합니다.
